# Public / Proprietary IP Boundary

## Publicly documented

IKHMAD publicly documents:
- product purpose;
- system architecture;
- user workflows;
- public API surface;
- basic data structures;
- synthetic examples;
- roadmap;
- high-level descriptions of intelligence components.

## Proprietary / confidential

IKHMAD does not publicly disclose:
- calibrated source-reliability logic;
- exact incident-confidence computation;
- risk weights and operational thresholds;
- internal hazard-prediction implementation;
- ETA-dependent road-safety calculations;
- predictive route-scoring implementation;
- safe-zone ranking formula;
- route-resilience / escape-fragility logic;
- false-report / fraud models;
- internal datasets and calibration results;
- unreleased patent-sensitive mechanisms.

## Why this boundary exists

Some components may be better protected through:
- trade-secret controls;
- patent filings;
- copyright;
- contractual confidentiality;
- controlled repository access.

Public documentation is therefore intentionally architectural rather than exhaustive.
